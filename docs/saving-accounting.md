# 节能效果核算与验证

> 模块：`backend/src/main/java/com/smarten/module/saving`
> 依赖：P5 动态基线（逐小时基线）+ P7 整改任务（观察起点）。

---

## 1. 核算公式

对观察期内每个小时 `i`：

```
节能量_i = 修正后动态基线_i − 实际能耗_i
节能量   = Σ 节能量_i
节能率   = 节能量 / Σ 修正后动态基线_i × 100%
节能金额 = Σ (节能量_i × 分时电价_i)
```

- **修正后基线**：来自该设备当前生效的 P5 模型，逐小时按产量、负荷、温度、班次等工况预测，不是整改前后总能耗相减。
- **分时电价**：默认 0.65 元/kWh；峰段（8–11、13–17）×1.2，谷段（22–6）×0.5，平段 ×1.0。
- 允许节能量、节能金额为负（峰段增耗会把金额拉低，即使总电量略降）。

---

## 2. 观察期与校验

| 项 | 规则 |
| --- | --- |
| 观察起点 | 优先整改完成时间，其次审核通过时间 |
| 观察周期 | 默认 7 天，可传 `observationDays` |
| 结束时间 | 起点 + 周期，且不超过当前时间 |
| 数据完整性 | 有效小时数 / 应有时长 ≥ 80%，且有效天数 ≥ 7 |
| 工况可比性 | 观察期平均产量相对整改前变化 ≤ ±30% |
| 停机判定 | 观察期内 ≥50% 小时停机 → 不判定为节能成功 |
| 基线版本 | 锁定并记录 `baseline_model_version` |

不满足完整性 → `数据不足待验证`；设备停机 → `停机不判定节能`；产量大幅变化 → `工况不可比`。

---

## 3. 核算结论

| 编码 | 结论 | 触发条件 |
| --- | --- | --- |
| 1 | 节能达成 | 数据完整、可比、未停机，节能率 ≥ 5% |
| 2 | 无明显变化 | 节能率 0–5% |
| 3 | 能耗恶化 | 节能量 < 0 |
| 4 | 数据不足待验证 | 完整率 < 80% 或天数 < 7 |
| 5 | 工况不可比 | 产量变化超出 ±30% |
| 6 | 停机不判定节能 | ≥50% 时间停机 |

判定顺序：数据不足 → 停机 → 不可比 → 恶化 → 无变化 → 达成。

---

## 4. 结果与追溯

每条结果保存：

- 观察周期、实际天数、样本天数、数据完整率
- 基线模型版本、修正后基线总量、实际总量、节能量、节能率
- 能源单价、节能金额（分时电价）
- 整改前/后平均产量、产量变化率、是否可比
- 结论与原因、逐小时明细（时间/基线/实际/节能量/电价）
- 版本号、是否历史版本、审核人/时间/意见

**复算**：同一任务再次核算会生成新版本，旧版本标记 `archived=1` 保留，可追溯对比。

---

## 5. 审核与任务联动

- 核算结果状态：0 待审核、1 已生效、2 已驳回。
- 审核通过：调用整改 `verify` 通过，任务从「效果验证中」进入「已完成」。
- 审核驳回：任务退回「整改中」，可重新整改后再次核算。
- 未审核的核算结果不会改变任务状态。

## 6. 接口

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/saving/tasks/{taskId}/calculate` | `saving:calc` | 执行核算（可重复，生成新版本） |
| GET | `/api/saving/results` | `saving:view` | 列表（任务/设备/状态/结论/日期） |
| GET | `/api/saving/results/{id}` | `saving:view` | 详情（逐小时对比 + 历史版本） |
| POST | `/api/saving/results/{id}/confirm` | `saving:audit` | 审核通过/驳回 |
| GET | `/api/saving/summary` | `saving:view` | 累计节能、排名、趋势 |
| GET | `/api/saving/export` | `saving:export` | 导出 CSV（含 BOM，Excel 可直接打开） |

## 7. 测试

### 单元测试（`SavingCalculatorTest`，8 个）

| 场景 | 断言 |
| --- | --- |
| 节能达成 | 节能量 336 kWh、节能率 20%、金额 > 0 |
| 无明显变化 | 节能率 < 5%，结论 NO_CHANGE |
| 能耗恶化 | 节能量为负，结论 NEGATIVE |
| 产量变化 +50% | 标记不可比，结论 NOT_COMPARABLE |
| 长期停机 | 结论 STOPPED，不判节能 |
| 观察期 3 天 | 结论 INSUFFICIENT |
| 分时电价 | 峰段 > 平段 > 谷段 |
| 重复计算 | 结果完全一致 |

### 集成测试（`SavingFlowTest`，3 个）

1. 核算 → 复算（版本 2、旧版本归档）→ 审核通过 → 任务完成 → 汇总排名。
2. 仅 2 天数据 → 数据不足待验证 → 驳回 → 任务退回整改。
3. 导出 CSV 含表头、核算明细与任务号。

全量测试：**67 个用例通过**。

## 9. 已知边界

1. 观察期以整点小时为粒度，依赖 P5 基线明细与生产工况；缺数据的时段不计入。
2. 产量变化阈值（±30%）、完整率（80%）、判定节能率（5%）当前为默认参数，后续可做成企业级配置。
3. 分时电价使用固定峰谷时段，未接入当地电网日历（节假日/尖峰）。
4. 审核通过即完成任务；若需“观察期结束后自动核算”，可在 P8 基础上增加定时任务。
